# 朋友圈助手 v0.2.2 设计方案：兼容微信 4.x（第二轮修订，待终审）

- 日期：2026-11-21
- 沿革：v0.2（首发）→ DSH 第 1 轮：需改后通过（P0-1/2/3）→ v0.2.1 → 第 2 轮：P0 全解决，遗留 P1-7、A7 及两处新引入问题 → 本稿

## 〇、本稿只改四处（其余同 v0.2.1）

| 编号 | 问题 | 本稿定稿写法 |
|---|---|---|
| N1 | PrintWindow 整窗位图 → 客户区裁切的**坐标口径**未写清（绝对屏幕坐标 vs 位图局部坐标） | 明确三段式：`GetWindowRect` 得 `wr`；`GetClientRect` 得 `cr`；`ClientToScreen(hwnd,(0,0))` 得 `c0`；**位图局部偏移 = `(c0.x - wr.left, c0.y - wr.top)`**，裁切框 `box=(dx, dy, dx+cr.width, dy+cr.height)`；位图尺寸严格等于 `wr.width × wr.height`；裁剪越界即判失败转降级 |
| N2 | 「唯一色 < 4」与均值/方差的口径不清，若按 OR 组合会重现 v0.2 的误判 | 三条件**全部满足**才判黑：`mean < 8 and pstdev < 2 and uniq_colors < 4`；`uniq_colors` 定义为 128×128 缩略图量化到 RGB 各 32 级后的唯一色数；判黑日志记三元组实际值 |
| P1-7 | 抑制期只是推迟 3 秒，微信不在前台时仍会被轮询隐藏，属"打补丁" | 改为**可见性模型**：引入 `self.pinned` 布尔。托盘单击／单实例唤起 → `pinned=True` 并 `show()`；`poll()` 只在 `not self.pinned` 时按前台规则 hide；`pinned` 在用户点「隐藏」、或托盘取消「常显」、或微信重新进入前台再离开时清零。取消 3 秒 magic number |
| 遗漏 1 | A7 桩用类名构造，而类名已不作判据，属自证 | 桩按 3.x 真实形态构造：进程名 `WeChat.exe`、类名 `WeChatMainWndForPC`、单窗无 Qt 子窗；断言"选中该窗"且"类名不参与判据"（把类名置空仍应选中） |

## 一、根因与证据

| 项 | 实测 |
|---|---|
| 微信进程 | `Weixin.exe`（4.x） |
| 微信窗口类名 | `Qt51514QWindowIcon` |
| 代码写死类名 `capture.py:10` | `WeChatMainWndForPC`（3.x） |
| 旧逻辑命中 | 0 |
| 按进程名枚举命中 | 2 个可见顶层窗 |
| PrintWindow(PW_RENDERFULLCONTENT) 本机 4.x 实测 | 成功且清晰（mean 220.5／stddev 73.2） |

两条独立缺陷：① 找不到窗（类名写死，`capture.py:10,14-24`）；② 找到了也没反馈（浮窗无托盘、启动即隐藏，`overlay.py:24-33`、`main.py:40-56`）。附带：配置落 `_MEIPASS`（`vision.py:9`）、GDI 截图不可靠（`capture.py:40-46`）。

## 二、改动清单

### F1 选窗（P0-1）

- 枚举：`EnumWindows` → `GetWindowThreadProcessId` → `QueryFullProcessImageNameW`（`PROCESS_QUERY_LIMITED_INFORMATION`，失败跳过）→ 进程名 ∈ `{weixin.exe, wechat.exe}`（config `wechat_procs` 可覆盖）且 `IsWindowVisible`。
- 优先级：① 前台窗属于微信 → 用它；② 否则面积最大的可见微信窗；③ 无 → `None`。
- 类名白名单仅作日志提示，不作判据（A7 会验这一点）。
- 缓存 `resolve_target()` 2 秒，缓存目标窗；每轮 `IsWindow()` 校验。
- 签名：`find_wechat_window(enum_windows=None, proc_name_of=None, foreground_hwnd=None)`。

### F2 前台判定

`GetForegroundWindow()` → 进程名 ∈ 微信集合 → 在前台；`IsIconic` 判 False；前台是浮窗自己 → False。

### F3 托盘＋pinned 可见性模型（P1-7）

- `QSystemTrayIcon`：`显示浮窗 / 常显浮窗（勾选）/ 设置 API… / 退出`。
- 托盘单击或单实例唤起 → `pinned=True; show()`；`poll()` 仅在 `not pinned` 时 hide。
- `pinned` 清零条件：用户点浮窗「隐藏」、取消勾选常显、或微信前台→离开的转变。
- 图标 `ExtractIconEx(sys.executable)`，失败退 `QStyle.StandardPixmap`。

### F4 配置与日志（P0-3／P1-5）

- `src/paths.py`：`APP_DIR=%APPDATA%\MomentsAssistant`；`ensure_dirs()` 建 `APP_DIR` 与 `screenshots`，启动首调；`save()` 前再调。
- 读取＝字段级合并：`VL_*` env 覆盖同名键 → `APP_DIR\config.json` → 旧 `config.json`（存在即 copy 迁移，成功后旧文件改名 `.migrated`）。
- 保存失败在状态栏提示，不抛槽。
- 日志 `APP_DIR\app.log`（1 MB×3）：`startup`、`resolve_target`（hwnd/进程/尺寸）、`capture` 三元组、API 耗时、异常摘要；Key 只记后 4 位，不记请求体与完整 URL。
- 截图落 `APP_DIR\screenshots`，留最近 20 张。

### F5 截图（P0-2／P1-4／N1／N2）

1. `wr=GetWindowRect(hwnd)`；建 `wr.width×wr.height` 的 32 位位图；`PrintWindow(hwnd, mdc, 2)`。
2. `cr=GetClientRect(hwnd)`；`c0=ClientToScreen(hwnd,(0,0))`；`dx=c0.x-wr.left, dy=c0.y-wr.top`；裁 `(dx,dy,dx+cr.width,dy+cr.height)`；越界即失败。
3. 判黑：128×128 灰度 `mean<8 and pstdev<2 and uniq_colors<4`（三条件同时成立）。
4. 判黑降级 `GetDC(0)+BitBlt`；仍黑抛「微信 4.x 截图失败，请改用剪贴板模式」。
5. DPI：`SetProcessDpiAwarenessContext(PerMonitorV2)`，失败回退 `SetProcessDPIAware()`；仍在 `QApplication` 前调用；`QT_ENABLE_HIGHDPI_SCALING=1`，统一 `devicePixelRatio` 换算。
- **F5b**：浮窗「用剪贴板图片」按钮，直接读剪贴板位图生成草稿。

### F6 单实例（P1-6）

`Local\MomentsAssistant_v2` 互斥体；`QLocalServer` 同名；第二实例 `connectToServer` 发 `show`，首实例 `pinned=True; show()`。启动 3 秒无可见窗口 → 托盘气泡提示。

## 三、契约（不变）

OpenAI 兼容 `chat.completions`，`VL_API_BASE/VL_API_KEY/VL_MODEL`；空 base 视为未设置。输出只写剪贴板；不自动发送、不注入、不读微信数据库、不做风控规避。
