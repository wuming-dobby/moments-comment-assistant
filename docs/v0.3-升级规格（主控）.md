# v0.3 升级规格（主控定稿，2026-11-23）

> 依据：用户实测反馈四条（使用说明/免费通道限流与费用/UI 简陋与浮球/评论活人感）。
> 实现：Qoder（编码驱动，-m DeepSeek-V4-Pro，accept_edits，ponytail lite）。写域 src/tests；README 使用节可改、免责六条不动。
> 合规底线不变：零 UIA、零注入、零进程内存读写、不自动发送、数据不经手项目方。

## 一、朋友圈小圆球：可行性论证（结论：可行，零新增风险面）

**机制**：只读窗口枚举（EnumWindows），与 v0.2 按进程名选窗同一套，不读控件树、不读进程内存，合规暴露面不增加。

**真机实测改判（2026-11-23 13:02，主控只读枚举，用户已开朋友圈）**：本机微信 4.x（Weixin.exe）**没有独立朋友圈窗口**——16 个微信系窗口仅主窗「微信」可见，朋友圈由 WeChatAppEx 渲染在主窗内部。原标题匹配前提在本版本不成立，浮球显隐策略改为双分支：

**实现**：
1. `capture.find_moments_window()`：保留多候选标题匹配（「朋友圈」/「Moments」，兼容有独立朋友圈窗的旧版本）；本机返回 None 属预期，不是 bug。
2. `BallOverlay` 显隐双分支：**找到独立朋友圈窗→锚定该窗右上角**；**找不到（微信 4.x 常态）→微信主窗在前台时，浮球锚定主窗右上角内侧**（复用现有 wechat_in_foreground）。微信最小化/关闭→淡出隐藏。48px 半透明圆钮、置顶不抢焦点、可拖动；点击→截当前目标窗→走现有生成管线→草稿进剪贴板。
3. 托盘入口与右下角浮窗保留为备用入口。

**风险**：仅窗口标题随微信版本变化的适配成本（与 v0.2 选窗同类），无新增合规面。复核交付时按此口径核验。

## 二、提示词规格（活人感，核心交付）

### 2.1 替换 vision.py 的 SYSTEM_PROMPT 为以下模板（persona_block 运行时注入）

```
你就是用户本人，正在给微信好友的朋友圈写评论。按下面的人设和规矩写。

【人设】{persona_block}

【规矩】
1. 5~25个字，像真人随手打的字，口语。最多1个emoji，也可以不用。
2. 必须抓帖子里一个具体细节（那盘菜、那个地方、那只猫、那件事）来说。空泛夸奖一律不行。
3. 禁用：太棒了、为你点赞、精彩分享、必须支持、羡慕了家人们、绝绝子、yyds。不许连续感叹号，不许排比，不许上价值升华，不许广告腔。
4. 看帖子氛围定语气：
   喜事好消息→真诚祝贺，很熟的朋友可以轻微调侃；
   生病难过坏消息→简短关心，绝不幽默；
   日常风景美食→轻松，可以幽默；
   晒娃晒宠物→夸具体细节；
   工作加班→共情，不打鸡血。
5. 幽默只在帖子本身轻松时用，不强行抖机灵；拿不准就朴实真诚。
6. 玩笑尺度按人设里的熟络程度把握：「很熟」才调侃；「偏同事客户」客气克制，不拆台。

【范例】
晒红烧肉→"这色泽，米饭杀手啊"（好）／"太棒了！厨艺精湛，为你点赞！"（坏：广告腔）
晒娃"终于会走路了"→"恭喜，离离家出走又近一步"（好：熟人调侃，抓细节）／"宝宝好可爱，天天开心！"（坏：空泛）
加班深夜→"辛苦了，早点歇"（好）／"加油！奋斗的人最美丽！"（坏：打鸡血）

只输出评论正文，不要引号、解释或候选。
```

设计依据：humanizer 技能中文 AI 痕迹清单——四字夸奖堆砌、广告腔、升华上价值、排比、聊天机器人套话，全部写成负向约束；「抓具体细节」是去广告腔的第一规则；few-shot 好坏对照校准风格。「晒娃」范例取自公开朋友圈神评论合集（快传号 2026-05-12，360kuai.com），满足用户「结合网上评论」要求；调侃范例仅限「很熟」人设，避免一律搞笑。

### 2.2 persona_block 构造（配置页人设问卷，全本地）

新增四字段（config.json，均可选）：
- `VL_PERSONA_GENDER`：男/女/不填
- `VL_PERSONA_STYLE`：幽默调侃/温和真诚/简洁干脆（默认温和真诚）
- `VL_PERSONA_CATCHPHRASE`：口头禅，自由文本（如「哈哈哈」「好家伙」）
- `VL_PERSONA_CLOSENESS`：很熟/一般/偏同事客户（默认一般）

拼接：`性别：X；说话风格：X；口头禅：X；与好友熟络度：X`。全空时：`未填写，按普通朋友的分寸写，朴实真诚。`
隐私：人设与截图一样只发往用户自配的 API；README 使用节须写明这一点（免责第 4 条口径已覆盖，使用节补一句）。

### 2.3 调用参数

`max_tokens=40`（硬顶），`temperature=0.8`，timeout 60 不变。输出 strip 后若带首尾引号则去掉。

## 三、多通道与费用

1. **截图压缩（费用与速度的大头）**：vision.py 现在发全尺寸 PNG。改为长边≤800px、JPEG q75 再 base64。依据：未压缩 1920×1080 截图≈2600+ image token，顶穿 1200 预算；压缩后落到 600–900 区间（跑腿核验）。编码已实测：93KB PNG→25.2KB（27%），口径有效。
2. **重试＋备用通道（刚需，不是可选）**：429/1305/1302 类瞬态错误先主通道重试 2 次（2s/4s 退避），仍失败切备用通道。config 增加 `VL_FALLBACK_API_BASE/KEY/MODEL` 三项（一个备用槽，不做 N 通道框架），推荐备用＝魔搭 `Qwen/Qwen2.5-VL-7B-Instruct`（免费，跑腿核验）。配置页加备用通道折叠区。**编码实测：周日午前高峰智谱免费档 4 连 429（100%），重试救不回——README 必须如实写「免费池高峰会限流，属正常，自动重试或换通道」**。红线：不做多账号轮询/代理池；自动扣费通道（百炼/火山/智谱付费档）默认关，开启时明标「会产生费用」；付费兜底 FlashX 须用户显式开启。
3. **免费通道表**：按跑腿核验 `跑腿素材/v0.3-通道与费用核验.md` 更新 README：智谱 GLM-4.6V-Flash（免费主力，如实标高峰限流）／魔搭 ModelScope（免费，需绑阿里云实名）／百炼（100 万 token 90 天额度，**用尽自动扣费，默认关**）／火山试用（活动型待核）／Ollama 本地（零联网）。注册入口一律裸域名。
4. **费用口径**：单条评论预算＝输入≤1200 token（压缩图＋提示词）＋输出≤40 token。付费单价×预算＝每条费用，跑腿给算式；编码若本机已有用户配置的 key，实测一次报真实数。

## 七、v0.3.1 修订（2026-11-23 用户实测反馈，主控裁定）

1. **max_tokens 40→512（阻断 bug 根因修复）**：主控实测用户配置 deepseek-flash，`finish_reason=length`、`reasoning_tokens=40`、content 空——混合推理模型把 40 预算全烧在思考上，正文零输出，各通道皆然。512 上限覆盖思考＋正文；费用仍可忽略（最坏约 0.2 分/条）。原「40 硬顶」基于非推理模型假设，作废。单测同步改断言。
2. **浮球缩小＋偏移**：48→36px；锚定位置改「离微信右上角一段距离」：窗内右边距 48px、上边距 64px（写成常量便于调，拖动功能不变）。
3. **右下角备用浮窗默认隐藏**：config 增 `VL_SHOW_OVERLAY`（默认 0），配置页加开关「显示右下角备用浮窗」；托盘单击/pinned 唤起不受影响。
4. **「仅朋友圈页面显示球」取证结论（2026-11-23 16:39 两态对比）**：开/关朋友圈窗口句柄完全一致，页面切换在 Win32 层零痕迹，窗口信号路线判死。用户选 A（自动识别），Qoder 实现，见 §八。

## 八、v0.3.2 朋友圈页面识别（方案 A：截屏窄带＋系统 OCR，用户拍板）

**原理**：微信在前台时，截主窗客户区顶部窄带（高约 120px、全宽），用 **Windows 自带 OCR**（winsdk → Windows.Media.Ocr，本地、不联网）识别文字；含「朋友圈」→显示球，否则隐藏。合规面与现有截图同类（读屏幕＋本地处理），零 UIA、零进程读取。

**实现要点**：
1. 依赖 `winsdk`（pip，PyInstaller 需 `--collect-all winsdk`，build.spec 同步）。OCR 语言取系统用户配置（中文 Windows 自带中文 OCR）。
2. **OCR 必须在工作线程**（asyncio.run 包 winsdk 异步调用），UI 线程只读最新结果——断言 8 口径不变，轮询周期内 OCR 不阻塞事件循环。
3. 显隐优先级：独立朋友圈窗命中（旧版微信）→锚定该窗；否则微信前台→OCR 窄带判定；OCR 不可用（import 失败/无语言包/异常）→**降级回「微信前台即显示」＋日志一次性警告**，不让功能死掉。
4. config 增 `VL_BALL_MOMENTS_ONLY`（默认 1）；设 0 回到 v0.3.1 行为。配置页加开关「仅在朋友圈页面显示浮球」。
5. 窄带截图复用现有 PrintWindow/BitBlt 管线裁顶部，JPEG 压缩后送 OCR（OCR 吃 PNG 更稳，窄带小，PNG 即可）。
6. 已知误判：群聊名恰含「朋友圈」三字会误显示——接受，README/说明注一句。
7. 单测：OCR 函数注入打桩（含「朋友圈」→显/不含→隐/抛异常→降级显）；真机两态（用户开/关朋友圈）球随动；**打包 exe 后必须真机复验 OCR 可用**（winsdk 打包是已知坑点）。

**验收断言（编码跑）**：①打桩三态全过；②真机开朋友圈球现、切聊天页球隐（用户配合）；③exe 打包后真机 OCR 生效；④OCR 期间 UI 不阻塞；⑤红线扫描零命中（OCR 属屏幕读取，非进程读取）。
