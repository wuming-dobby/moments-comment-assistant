## 一、根因与证据

| 项 | 实测 |
|---|---|
| 微信进程 | `Weixin.exe`（4.x） |
| 微信窗口类名 | `Qt51514QWindowIcon` |
| 代码写死类名 `capture.py:10` | `WeChatMainWndForPC`（微信 3.x） |
| 旧逻辑命中窗口数 | 0 |
| 按进程名枚举命中 | 2 个可见顶层窗 |
| PrintWindow(PW_RENDERFULLCONTENT) 本机 4.x 实测 | 成功，画面清晰（mean 220.5／stddev 73.2，截到的是登录窗） |

三个症状拆成两条独立缺陷（**修正 v0.2 的因果表述**）：

1. **找不到窗**（类名写死）→ 浮窗永不显示、点生成只报「没找到微信窗口」（`capture.py:10,14-24`；`overlay.py:11-16,54-62`）。
2. **找到了也没反馈**（浮窗 `Qt.Tool`＋无边框＋无托盘，启动即隐藏）→ 观感「双击没反应」（`overlay.py:24-33`；`main.py:40-56`）。此条与类名无关，由 F3／F6 单独解决。

附带隐患：配置落 `_MEIPASS` 临时目录（`vision.py:9`）；GDI 截图对 4.x 不可靠（`capture.py:40-46`）。

## 二、改动清单

### F1 窗口识别与选窗规则（P0-1）

- 位置：`src/capture.py`
- 枚举：`EnumWindows` → `GetWindowThreadProcessId` → `QueryFullProcessImageNameW`（`PROCESS_QUERY_LIMITED_INFORMATION`，失败跳过）→ 进程名 ∈ `{weixin.exe, wechat.exe}`（config `wechat_procs` 可覆盖）且 `IsWindowVisible`。
- **选窗优先级**：① `GetForegroundWindow()` 属于微信进程 → 用它（朋友圈是独立窗，看什么截什么）；② 否则取面积最大的可见微信窗；③ 都无 → `None`。
- 类名白名单 `{WeChatMainWndForPC, Qt51514QWindowIcon}` 仅作快路径提示，不作判据。
- 缓存：`resolve_target()` 缓存 2 秒，缓存的是「目标窗」而非「主窗」；每轮 `IsWindow()` 校验，失效重算。
- 签名：`find_wechat_window(enum_windows=None, proc_name_of=None, foreground_hwnd=None)`，三个依赖可注入供单测。

### F2 前台判定

- 位置：`src/overlay.py:11-16`
- 取 `GetForegroundWindow()` → 进程名 ∈ 微信进程集合 → 视为在前台；`IsIconic` 仍判 False。
- 前台窗是浮窗自己（进程非微信）→ 判 False，靠 F3 抑制期抵消点击瞬间闪烁。

### F3 托盘＋常显开关＋抑制期（P1-7）

- `QSystemTrayIcon`，菜单：`显示浮窗 / 设置 API… / 退出`；左键单击 → `suppress_until = now+3s` 并 `show()`。
- `poll()` 开头：`if now < self.suppress_until: return`。
- 图标：`ExtractIconEx(sys.executable)`，失败退回 `QStyle.StandardPixmap`。
- 「常显浮窗」写入 config，勾选后 `poll()` 不 hide。

### F4 配置与日志（P0-3／P1-5）

- 新模块 `src/paths.py`：`APP_DIR = %APPDATA%\MomentsAssistant`；`ensure_dirs()` 建 `APP_DIR` 与 `APP_DIR\screenshots`，启动第一件事调用。
- config：`APP_DIR\config.json`。读取＝**字段级合并**：`VL_*` 环境变量覆盖同名键 → 否则 `APP_DIR\config.json` → 再否则旧 `config.json`（存在即一次性 copy 迁移，成功后将旧文件改名 `.migrated`）。
- 保存：`save()` 先 `ensure_dirs()`；`write_text` 包 try，失败在状态栏显示「保存失败：<原因>」。
- 日志：`APP_DIR\app.log`（1 MB×3 轮转）；记 `startup`、`resolve_target`（hwnd/进程/尺寸）、API 耗时、异常摘要。**脱敏**：Key 只记后 4 位，不记请求体与完整 URL。
- 截图临时文件改落 `APP_DIR\screenshots`，保留最近 20 张。

### F5 截图：整窗 PrintWindow → 裁客户区，黑图判定改 AND（P0-2／P1-4）

1. `GetWindowRect` 建 32 位位图（含边框），`PrintWindow(hwnd, mdc, 2)`；
2. `GetClientRect` + `ClientToScreen(hwnd,(0,0))` 求偏移，裁出客户区；
3. 判黑（改 AND）：整图缩到 128×128 灰度，`mean < 8 and pstdev < 2` → 判黑；另加「唯一色 < 4」判纯色；
4. 判黑降级 `GetDC(0)+BitBlt`（v0.1 路径）；仍黑 → 抛「微信 4.x 截图失败，请改用剪贴板模式」；
5. DPI：`SetProcessDpiAwarenessContext(PerMonitorV2)`，失败回退 `SetProcessDPIAware()`；仍在 `QApplication` 之前调用；设 `QT_ENABLE_HIGHDPI_SCALING=1`，统一用 `devicePixelRatio` 换算。
- **F5b 兜底（同版上）**：浮窗加「用剪贴板图片」按钮，直接读剪贴板位图生成草稿。

### F6 单实例与启动反馈（P1-6）

- 互斥体 `Local\MomentsAssistant_v2`（存在则退出）；`Global\` 仅兼容尝试，失败不报错。
- 唤起：`QLocalServer` 命名 `MomentsAssistant_v2`；第二实例 `connectToServer` 发 `show`，首实例收到后 `suppress_until=now+3s; show()`。
- 启动 3 秒内无可见窗口 → 托盘气泡「已在后台运行，微信前台时显示浮窗」。

## 三、契约（不变）

- 模型：OpenAI 兼容 `chat.completions`，三项 `VL_API_BASE / VL_API_KEY / VL_MODEL`；空 `VL_API_BASE` 视为未设置，不传给 client。
- 输出：只写剪贴板；**不自动发送、不注入、不读微信数据库、不做风控规避**。

## 六、风险

- R1 PrintWindow 对本机 4.x **已实测可用**；保留降级与剪贴板兜底，不引 winrt/WGC 重依赖。
- R2 进程名/类名再变 → config `wechat_procs` 可改；`resolve_target` 结果写日志便于现场定位。
- R3 PerMonitorV2 与 PyQt5 缩放冲突 → 按 F5-5 统一换算，异常回退 `SetProcessDPIAware`。
